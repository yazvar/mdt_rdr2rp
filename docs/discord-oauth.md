# Discord OAuth2

Вход в MDT только через Discord. Имя пользователя не является идентификатором: сервер хранит неизменяемый Discord ID.

Секрет приложения остаётся в переменных API на Railway. В Electron его нет.

## Приложение в портале Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) и создайте приложение, например `Sheriff MDT`.
2. В **OAuth2** скопируйте Client ID и сгенерируйте Client Secret.
3. В Redirects добавьте ровно один адрес:

```text
https://<публичный-домен-api>/api/auth/discord/callback
```

Для локальной проверки это `http://localhost:3000/api/auth/discord/callback`. Адрес должен совпадать с `{API_PUBLIC_URL}/api/auth/discord/callback`. Слэш в конце `API_PUBLIC_URL` не нужен.

4. Scope оставьте `identify`. Почта, серверы и сообщения для входа не запрашиваются.
5. Положите ID и секрет в переменные сервиса `mdt-api`: `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_OAUTH_SCOPES=identify`.

## Как проходит вход

1. Приложение просит API начать вход.
2. API создаёт попытку, сохраняет `state` и проверочную строку PKCE и отдаёт адрес Discord.
3. Системный браузер открывает Discord. Окно MDT этот адрес само не загружает.
4. Discord возвращает код на API. Секрет и PKCE сверяются на сервере.
5. Страница в браузере не показывает токен. Она просит вернуться в MDT.
6. Приложение опрашивает попытку и один раз забирает сессию. Повторный опрос токен уже не отдаёт.
7. Сервер ищет Discord ID среди допущенных сотрудников. Нет допуска — сессия не создаётся.

Сессия хранится как случайный токен. В базе лежит только его хеш с солью `SESSION_PEPPER`. Срок сдвигается при работе и не превышает `SESSION_ABSOLUTE_DAYS`. Выход и отзыв сессии в админ-панели гасят доступ сразу. Смена прав отключает открытые сокеты этого пользователя.

## Первый администратор

В `BOOTSTRAP_DISCORD_IDS` перечислите числовые Discord ID через запятую. Узнать ID можно в Discord: настройки пользователя, расширенный режим, «Копировать ID пользователя».

Когда этот человек впервые входит через OAuth, API создаёт ему учётную запись и роль администратора. Остальные ID без заранее выданного доступа получают отказ.

Демонстрационные ID вида `TEST-DISCORD-SHERIFF` в этот список не входят и для настоящего Discord не годятся.

## Локальная проверка без Discord

В `.env` для разработки:

```text
ALLOW_DEV_LOGIN=true
NODE_ENV=development
```

На экране входа появятся тестовые карточки после `npm run db:seed`. В production API с этим флагом не стартует.
