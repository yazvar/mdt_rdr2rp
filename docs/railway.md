# Railway

Нужны три сервиса в одном проекте Railway. Пользователь на Windows ставит только приложение. К PostgreSQL с его компьютера доступа нет.

| Сервис | Что это | Корень репозитория | Файл конфигурации |
|---|---|---|---|
| `mdt-database` | PostgreSQL | — | шаблон Postgres |
| `mdt-api` | Express | корень репозитория | `apps/api/railway.toml` |
| `mdt-bot` | Discord-бот | корень репозитория | `apps/bot/railway.toml` |

Корень сервиса API и бота — весь репозиторий, не папка `apps/api`. Иначе Docker не увидит `package.json`, Prisma и общий пакет. Путь к Dockerfile в toml уже указывает на `apps/api/Dockerfile` и `apps/bot/Dockerfile`.

Держите по одной реплике API и бота. Обновления между окнами идут через Socket.IO и запасной опрос `/api/sync`. Несколько реплик без общего Redis пропускают часть мгновенных событий; опрос их догоняет, но одна реплика проще.

## База

1. Создайте сервис PostgreSQL и назовите его `mdt-database`.
2. В сервисах `mdt-api` и `mdt-bot` добавьте переменную `DATABASE_URL` ссылкой на Postgres (`${{mdt-database.DATABASE_URL}}`).
3. Не включайте автоматический сброс базы при деплое. Образ API выполняет только `prisma migrate deploy`. Команд `migrate reset` и `db push` в запуске нет.

Миграции лежат в `prisma/migrations`. Новая миграция создаётся локально командой `npx prisma migrate dev` и попадает в git. На сервере она только применяется.

При старте API несколько раз проверяет `SELECT 1`. Если база ещё поднимается, процесс подождёт. Если базы нет, `/health` отвечает `503`.

## API

Публичный домен включите у `mdt-api`. Railway передаёт порт в `PORT`, процесс слушает `0.0.0.0`.

Переменные сервиса `mdt-api`:

| Ключ | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | ссылка на Postgres |
| `API_PUBLIC_URL` | `https://…up.railway.app` без слэша в конце |
| `SESSION_PEPPER` | длинная случайная строка |
| `DISCORD_CLIENT_ID` | из портала Discord |
| `DISCORD_CLIENT_SECRET` | секрет приложения |
| `DISCORD_OAUTH_SCOPES` | `identify` |
| `BOOTSTRAP_DISCORD_IDS` | числовые Discord ID администраторов |
| `ALLOW_DEV_LOGIN` | не задавайте или `false` |
| `TZ_OFFSET_MINUTES` | `180` для Москвы, если округ живёт по этому времени |
| `SESSION_HOURS` | `24` |
| `SESSION_ABSOLUTE_DAYS` | `14` |

`ALLOW_DEV_LOGIN=true` в production останавливает API. Секрет Discord и перец сессий не попадают в установщик Windows.

Проверка после деплоя: `https://<api>/health` возвращает `"db":"up"`.

## Бот

Отдельный сервис из того же репозитория. Ему нужен публичный домен только для проверки здоровья Railway, пользователи туда не ходят.

| Ключ | Значение |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | та же база |
| `DISCORD_BOT_TOKEN` | токен бота |
| `DISCORD_CLIENT_ID` | id приложения, чтобы зарегистрировать команды |
| `DISCORD_GUILD_ID` | сервер департамента, чтобы команды появились сразу |
| `BOOTSTRAP_DISCORD_IDS` | те же администраторы, что у API |
| `API_HEALTH_URL` | `https://<api>/health` |
| `MDT_PUBLIC_URL` | пусто, если нет веб-страницы MDT |

Бот читает очередь `Outbox` в PostgreSQL. Повторная обработка того же события не шлёт второе письмо: у события есть ключ дедупликации, у каждого получателя своя запись доставки.

## Обновления программы

У сервиса `mdt-api` создайте том и примонтируйте его в `/data`. Без тома опубликованный установщик исчезнет при следующем деплое.

| Ключ | Значение |
|---|---|
| `UPDATES_DIR` | `/data/updates` |

Администратор публикует новую сборку из вкладки «Обновление». Файлы отдаются по адресу `https://<api>/updates`. Это не секрет: установщик и так ставится на компьютеры сотрудников.

Держите одну реплику API. Иначе загруженный файл окажется только на той реплике, которая приняла запрос, если том не общий.

## Приложение

В `apps/desktop/.env.production` запишите `VITE_API_URL` равным `API_PUBLIC_URL`. Затем на машине разработчика:

```bash
npm run build:win
```

Раздайте `apps/desktop/release/*.exe`. После смены домена API нужна новая сборка: адрес вшивается в интерфейс на этапе Vite и секретом не является.

## Что проверить перед службой

- `/health` показывает живую базу
- миграции применились без удаления таблиц
- вход администратора из `BOOTSTRAP_DISCORD_IDS` открывает админ-панель
- чужой Discord ID видит отказ, а не пустой кабинет
- бот после рестарта снова пишет `bot ready` в логах
- две копии приложения видят новую карточку без переустановки
- обрыв сети показывает «Архив недоступен» и не сообщает об успешном сохранении
- копия базы скачивается и контрольная сумма сходится
