# Резервные копии

Архив департамента не удаляется при выкладке. `prisma migrate deploy` только добавляет миграции.

## Копия из админ-панели

Администратор открывает «Архив базы» и скачивает JSON. Формат файла — `mdt-backup-v1`. Внутри таблицы и контрольная сумма SHA-256 содержимого. Секреты Discord в этот файл не входят: их нет в базе. В базе есть Discord ID, карточки сотрудников, штрафы и журнал. Храните файл как служебный документ.

Скачивание само записывается в журнал действий.

## Восстановление

1. Выберите скачанный JSON.
2. Введите фразу `ВОССТАНОВИТЬ АРХИВ` без кавычек.
3. Подтвердите.

Сервер проверяет формат и сумму. Если файл изменён, восстановление не начинается. Старый журнал действий сохраняется и дополняется записью о восстановлении. Действующему администратору заново выдаётся роль и новая сессия, остальные сессии гаснут. Демонстрационные и служебные записи при этом не стираются молча: они возвращаются к состоянию файла.

Обычный экран не умеет очистить журнал или стереть штраф без следа. Удаление юридических записей через интерфейс не предусмотрено: карточки архивируются, дела закрываются, статьи отменяются.

## PostgreSQL на Railway

Включите резервные копии у сервиса `mdt-database` в панели Railway, если тариф их даёт. Это снимок всего кластера и не зависит от JSON в админ-панели.

Снять копию вручную с машины, у которой есть `DATABASE_URL`:

```bash
pg_dump --format=custom --no-owner --file mdt.dump "%DATABASE_URL%"
```

Восстановление останавливает запись на время замены. На чистой базе:

```bash
pg_restore --clean --if-exists --no-owner --dbname "%DATABASE_URL%" mdt.dump
```

После `pg_restore` не запускайте `prisma migrate reset`. Если схема отстала от кода, примените только `npx prisma migrate deploy`.

Проверка: `/health` отвечает `"db":"up"`, администратор входит прежним Discord ID, последняя известная карточка на месте.

Каталог `BACKUP_DIR` в `.env` необязателен. Рабочая копия для сотрудников — кнопка в админ-панели и снимок Railway.
