# Discord-бот

Бот только доставляет письма и отвечает на три команды. Он не читает чужие сообщения и не управляет ролями сервера.

## Создание

Используйте то же приложение Discord, что и для входа.

1. Раздел **Bot**, кнопка Reset Token. Токен сохраните в `DISCORD_BOT_TOKEN` сервиса `mdt-bot`. В git и в установщик он не кладётся.
2. Привилегированные intent не включайте. Бот запускается с intent `Guilds`. Содержание сообщений и список участников ему не нужны.
3. В **OAuth2 → URL Generator** отметьте scope `bot` и `applications.commands`. Права бота: отправка сообщений не обязательна для личных писем, но бот должен состоять на сервере департамента. Достаточно приглашения без прав администратора.
4. Пригласите бота на сервер департамента.
5. В переменных бота укажите `DISCORD_CLIENT_ID` и `DISCORD_GUILD_ID`, чтобы команды зарегистрировались на этом сервере сразу. Без `DISCORD_GUILD_ID` команды станут глобальными и могут появиться через час.

## Кто получает письма

Личное сообщение доходит, если пользователь состоит с ботом на одном сервере и не запретил личные сообщения от участников сервера. Если Discord отвечает `50007`, `50001` или `10013`, попытка больше не повторяется: это постоянный отказ. Временная ошибка повторяется не больше пяти раз, с паузой.

Получатели нового запроса снаряжения — сотрудники с правом рассмотрения запросов и дополнительные Discord ID из админ-панели. Письмо выглядит так:

```text
**SHERIFF DEPARTMENT — NEW EQUIPMENT REQUEST**
**Deputy:** имя
**Badge Number:** табельный номер
**Requested Item:** предмет
**Quantity:** количество
**Reason:** причина
**Request ID:** #EQ-00001
**Status:** Pending Review

Open MDT to review this request.
```

Если задан `MDT_PUBLIC_URL`, бот добавляет эту ссылку. Иначе пишет открыть MDT.

Одобрение и отклонение уходят автору запроса. Повтор того же события не создаёт второе письмо: ключ события уникален, доставка каждому получателю учитывается отдельно.

Очередь лежит в таблицах `OutboxEvent` и `OutboxDelivery`. Бот забирает её каждые четыре секунды. API и бот могут перезапускаться независимо.

## Команды

Доступны администраторам из `BOOTSTRAP_DISCORD_IDS` и пользователям с правом `admin.access`.

| Команда | Действие |
|---|---|
| `/mdt-status` | Доступен ли API и сколько писем ждёт очереди |
| `/mdt-notify` | Проверочное личное сообщение себе или указанному пользователю |
| `/mdt-help` | Список команд |

## Логи

Ошибки отправки пишутся в журнал Railway и в таблицу системных ошибок. Их видно в админ-панели, вкладка «Ошибки». Токен в текст ошибки не попадает.

Без `DISCORD_BOT_TOKEN` в development процесс поднимает только `/health` и не подключается к Discord. В production отсутствие токена останавливает бота.
